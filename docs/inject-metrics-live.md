## 结论

1. **省是真省**：65 KB 大策略上，闲聊/普通代码请求的输入 token 从 ~19.8k 降到 ~90–100，**降幅 99.5%+**；
   全站若一半请求是非技术类，输入成本直接砍半以上。
2. **该花的地方没省**：重技术请求仍然走全文，prompt_tokens 与 always 基本一致。
3. **标记块有固定开销**：`<!-- ZAKO:BEGIN … -->` 两行带来约 **37–39 token**。
   相对 19.7k 可忽略（0.2%），但在 4.7 KB 小策略上占 3%。已列为可优化项。
4. **校准问题被真实数据确认**：`轻技术`（普通写代码）只命中「报错」1 分 → 落 off，
   注入量归零。若用户装破甲就是为了写代码时不啰嗦，这类请求会被整条漏掉。

## 据此做的两项修正

1. **代码任务加成**：请求里出现 `脚本/函数/接口/代码/编程/调试/部署` 等词，额外 +2（只加一次）。
   轻技术场景 1 → 3 分，落 `frame`（只注身份帧），不再归零。
2. **补渗透词**：加入 `靶场(3) / 内网(3) / 信息收集(2) / webshell(3)`。
   渗透场景 3 → 8 分，落 `full`，不再只给身份帧。
3. **标记块瘦身**：begin 行去掉 `tier=` 后缀，end 行不再重复 profile id，省约 10 token。
